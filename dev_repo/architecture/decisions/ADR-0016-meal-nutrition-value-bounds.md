# ADR-0016 餐食营养值域上限

状态：approved（C-26-A1）  
日期：2026-08-22

## 背景

`MealRecord` 的营养字段此前只有非负校验。超长数字在浏览器 `Number` 转换时可能丢失精度，
仍可作为天文数字进入数据库，并在首页、日历和报告中撑破内容布局。项目已有档案、识别
结果和活动数据的合理值域约束，餐食记录需要与其保持同一防御边界。

## 决策

1. `calories`、`protein_g`、`fat_g`、`carbs_g` 的服务端允许范围统一为 `0–100000`
   （含边界），创建、批量创建和更新共用同一 helper。
2. 前端输入声明相同的 `min`/`max` 边界；非有限值和超长数字不得静默转换成可保存的 0。
   保存前以用户可读提示拒绝，识别审核草稿沿用同一规则。
3. 历史记录不迁移、不回填、不删除。展示 helper 对旧库中的非有限或超大值使用短的受控
   文本，避免布局破坏；这不是对历史事实的改写。
4. 该变更只收紧应用层值域，不新增表、字段、索引、关系或 Prisma migration。

## 不变的边界

- `MealRecord` 的主键、`UserProfile` 所有权、日期/餐别语义和 `/api/meals` 响应封套不变。
- 识别图片、Agent、记忆、运动计划和文章数据边界不变。
- 旧数据库和现有合法餐食记录保持原样；Issue #10 在外部复测前保持开放。

## 验证

- 契约测试覆盖 0、100000、100001、负数、`Infinity` 和超长数字，并覆盖创建/批量/更新。
- 手动录入与识别审核在 `/meals` 页面显示明确拒绝提示。
- 首页、日历、报告对历史异常值不产生横向溢出；lint、typecheck、build 通过。
